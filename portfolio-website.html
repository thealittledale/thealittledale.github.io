01

The Brief

I wanted a portfolio I could host anywhere and keep adding to myself as my final-year work develops. Above all, it had to read as a considered piece of graphic design in its own right, not a generic template.

02

Design Theory

The design borrows from risograph printing, with its flat, layered and slightly messy ink overlays. I wanted the site to have a little of the feel of a zine or a poster, with halftone dots and two-colour overprint.

The layout follows editorial-design conventions rather than web ones: asymmetric grids, oversized type and a ticker along the top, all borrowed from print magazines.

03

Typography & Colour

I used three typefaces. Fraunces, a characterful, slightly wonky optical serif, carries my name and the headlines. Archivo, a grotesk sans, is for body copy and labels. Space Mono is for tags, dates and navigation.

The colour palette was built around the riso concept: a paper-coloured neutral background, with cobalt blue and magenta standing in for risograph inks. Keeping to two accent colours, plus a moss green for small labels, stops the page from being too busy and gives a consistent motif from the hero text through the rest of the site.

04

Layout, Motion & Interaction

  • Asymmetric grid. Project tiles change width from row to row, so the site doesn't look like a uniform template.
  • Halftone overprint. I designed a dot motif in Illustrator and brought it into Figma. On the site it's recreated in code and sits at the top of every page like an overprint.
  • Scrolling marquee. A ticker of skills under the navigation, borrowed from print mastheads and gig posters.
  • Custom cursor and hover states. I designed a cursor that expands over links and project tiles, so the site feels a little different to use.
05

Build & Hosting

I'd never built a website before, so I started by talking my options through with Claude. That led me to Claude Code, and Claude taught me how to use it so I could turn my Figma design into a working site myself.

I used Claude's Cowork mode so it could work directly with the files on my computer: my project reports, images and videos. It then talked me through setting up a GitHub account to store the website's code, and using GitHub Pages, which hosts sites like this one for free.

Now when I want to change something, I describe it, preview the change in my browser, and only publish it when I'm happy.
